# concept-check · 概念核验

## 核心判断

判断一个词/一个概念，有两层深度，别搞混：

- **A 层（贴身词语核验）**：这个词是不是万能空词——放哪个话题都通用、没有具体指向。三问自检就够了。
- **B 层（深度概念拆解）**：这个概念本身是不是没被想清楚——不同人说着同一个词其实各说各话，或者这个词的存在本身就在掩盖一处思考的空白。三问自检查不出这个，得走完整套拆解动作。

用户要"帮我拆一下这个概念""这个词到底什么意思""大家说的是一回事吗"，是要 B 层。只给一个"这是不是空词"的判断就收工 = 拿 A 层的活儿搪塞 B 层的要求，等于没拆。

## 什么时候调用

- **A 模式**：写文案时纠结某个形容词/状态词该不该用。
- **B 模式**：讨论中冒出一个模糊概念，想彻底想清楚它——「私域到底是什么」「大家说的复利是一回事吗」「这个词是不是包装」。有人要求"更高级""更有深度"的表达时，也先用 B 模式查清楚：是词的问题，还是判断本身就不够狠。

## 不要做什么

- 不要拿 A 模式的三问自检应付 B 模式的请求。用户要深度拆解，走完下面 B 模式全部步骤，不许中途喊停。
- 不要看到抽象词就无脑判空词。先过行业黑话豁免——赛道黑话（内化/私域/认知/流量/转化/涨粉/完播）对目标受众有具体指向，不该被换成生造的画面词。
- 不要用"炼语言"回应"要更高级"的要求。意象、警句、华丽词是装，不是深度；深度是判断链条能不能一层一层往下问"为什么"。
- 不要给伪概念找台阶。一个词经不起"去掉它、大白话还能不能说清楚"的检验，直接说它是包装，不装懂。
- 不要堆一堆正确的废话搪塞。每一步都要落到"这个概念具体错在哪/具体指什么"，说不出具体的就是没拆到位，回去重拆。

## A 模式：贴身词语核验（写文案时用）

### 步骤 1：三问自检

对每个可疑词过一遍：

1. 能让人立刻想到画面吗？
2. 能把你和别的做法区分开吗？
3. 能帮人排除掉某些做法吗？

三个都不能 → 空词，找替代。任一个能 → 保留。

**已验证的空词黑名单**：克制、质感、高级感、氛围感、调性、扛不住、撑不住、冷/冷清、边界感、体积感、立住/立得住。

**替换方向实例**（抽象状态词 → 画面动作词）：

| 空词 | 画面动作词 |
| --- | --- |
| 家还是冷的 | 进门像走进还没人住的样板间 |
| 撑不出"住进去这一档" | 业主住进去半年还是把家当酒店住 |
| 整面墙才压得住 | 整面墙看进眼里才有东西可看 |
| 态度立住了 | 不用说自己较真，这一句就够了 |

### 步骤 2：行业黑话豁免检查

判空词之前先问：**这是目标受众赛道本来就用的词吗？**

- 是（内化、私域、认知、思维、流量、转化、涨粉、完播这类自媒体/商业黑话，受众天天在用、听得懂、用得上）→ 正常用，不用换成画面词。硬凹一个生造的具象比喻（比如把"内化"换成"身体不疼"），反而显得搞笑，不像真人会说的话。
- 不是（放哪个赛道都通用、没有行业指向）→ 走步骤 1 三问自检。

**判断顺序：先问是不是行业词，不是才查空词三问**，顺序反了会把有效行话误杀。

## B 模式：深度概念拆解（四步走完，不是查完表就收工）

### 步骤 1：对齐一下——是不是在说同一件事

这个词在不同人嘴里是不是一个意思？逐个列：

| 谁在说 | 他嘴里这个词具体指什么行为/结果 | 和别人一样吗 |
| --- | --- | --- |
| {使用者 1} | {含义 1，要具体到行为/结果，不能停在同义词替换} | |
| {使用者 2} | {含义 2} | |

同一个词几种人几种含义 → 各说各话，这本身就是问题所在：讨论下去之前得先钉死在说哪一种。如果这个概念本身跨了具体行业或专业领域，顺手把那个领域里"懂行的人怎么理解这个词"也列进对比表里的一行，别单独另起一段。

### 步骤 2：往回倒——这词原本指什么，现在跑偏在哪

- 这个词/说法最早是描述什么具体场景、具体事的？
- 剥掉场景，它唯一不变的意思是什么？
- 现在被搬到眼下这个场景里说，跟原来比，哪个部分被悄悄换掉了？换句话说：原本形容 A 类事的词，现在被拿来形容 B 类事，中间那个没说破的假设是什么？
- 顺带定个边界：什么情况下用这个词是准的，什么情况下已经算滥用。

### 步骤 3：两道测试，定死这词是真概念还是包装

**测试一 · 去词测试**：把这个词从句子里拿掉，用大白话能不能说清同一件事？
- 能 → 这个词只是包装，不影响理解，不用纠结。
- 不能 → 说明这个词在替你掩盖一处没想清楚的地方，先用大白话把那个空白填上，再决定这个词还要不要用。

**测试二 · 假装有标准答案测试**：这个概念是不是在假装"这事有一个唯一正确答案，只要找到/设计出来就行"——但实际上这事根本没有客观正确解，只有当事人自己的判断，换个人给的答案本来就该不一样？或者它是不是在假装"这东西能被人从上往下设计出来"——但实际上它是从大量具体实践里自然长出来的，没人能画张图纸把它设计出来？
- 命中一条 → 大概率是个**伪概念**：它给人一种"想明白定义就能解决问题"的错觉，实际唯一的解法是去真做、去试。
- 两条都没命中，先别直接放行——退一步换个问法：这个概念是不是在把一个更朴素的说法包装成了行话（比如把"大家做法不一样"包装成"没有护城河"）？是不是把一个只能靠反复试错才能验证的判断，说得像是能一次想清楚的定论？这两问也答不上来，才算真没查出问题，往下走步骤 4。

### 步骤 4：这事是信息缺口，还是执行缺口

这个概念背后的真问题，能不能靠一段文字回答完？

- **能**：写清楚就完了，是个信息缺口。
- **不能**：不管答案写多细，都得真去做、去试错、拿到反馈才知道对不对——大部分让人纠结的商业困惑其实是这一类，只是被包装成了"该有个标准答案"的样子，一直在等一个说不出来的答案，其实该做的是去试。

```
# 概念拆解：{概念名称}

## 表面意思
{这个概念通常被怎么理解}

## 是不是各说各话
{步骤 1 的对比表 + 一句话判断：一致还是各说各话}

## 往回倒：原本指什么，现在跑偏在哪
- 原本指：{...}
- 不变的核心：{...}
- 现在这么用，跑偏在哪：{...}
- 边界：{什么时候用它是准的，什么时候是滥用}

## 两道测试
- 去词测试：{拿掉词，大白话怎么说这件事}
- 假装有标准答案测试：{命中了哪一条，还是两条都没命中}
- 结论：{是不是伪概念}

## 信息缺口，还是执行缺口
{步骤 4 结论}

## 一句话
{把上面全部压成一句最直给的判断}
```

A 模式（贴身词语核验）输出更短：

```
{词}：{行业黑话，保留 / 空词，需替换}
判断依据：{三问结果 / 豁免检查结果}
{需要替换时给 2-3 个画面动作词候选}
```
